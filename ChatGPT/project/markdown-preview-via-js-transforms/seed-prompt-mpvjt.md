# 依頼：VS Code用Markdown変換プレビュー拡張機能の開発

## 1. 目的

VS Codeのワークスペース内にあるYAML・Markdown・Plaintextファイルを、ユーザーが作成したJavaScriptでMarkdownに変換し、VS Code標準のMarkdownプレビューに表示する拡張機能を開発してください。

設計・実装・検証・成果物の提供までお願いします。

開発は、`Dropbox\ai\development-and-operations-model\idad-v1.md` に定義されたIDAD（意図主導型AI開発）方式に従ってください。

Dropbox内の資料を参照する場合は、`Dropbox\ai\etc\sources.md` も確認してください。

## 2. 最重要要件

**変換処理とVS Code連携機能を明確に分離してください。**

変換処理はユーザー自身がJavaScriptで作成・編集します。内容はまだ決まっておらず、頻繁に変更する可能性があります。

したがって、JavaScriptの変更に伴って拡張機能を修正・再ビルドする必要がない構成にしてください。

また、VS Codeでは自動保存を使用していますが、ファイルが保存されても変換処理を自動実行しないでください。

**変換処理とプレビューの更新は、ユーザーの明示的な操作によってのみ実行してください。**

## 3. 必要な機能

### 3.1 対応ファイル

入力形式：

- YAML（`.yaml`、`.yml`）
- Markdown（`.md`）
- Plaintext（`.txt`）

いずれもテキストとしてJavaScriptへ渡します。

YAMLの解析やMarkdownへの変換は、拡張機能ではなくユーザー作成のJavaScriptが担当します。

### 3.2 JavaScriptによる変換

ワークスペース内の指定フォルダに、複数の変換JavaScriptを配置できるようにしてください。

例えば以下の構成です。

```text
workspace/
├── document.yaml
├── note.md
├── story.txt
└── transforms/
    ├── yaml-table.js
    ├── yaml-document.js
    ├── markdown-custom.js
    └── plaintext-novel.js
```

JavaScriptと拡張機能の間には、簡潔で安定したインターフェースを設けてください。

参考例：

```javascript
module.exports = async function ({ text, filePath }) {
  // ユーザーが自由に変換処理を書く
  return text;
};
```

入力にはファイル内容とファイルパスを含め、出力はMarkdown文字列とします。

必要であればインターフェースの改良を提案して構いません。

ユーザーが外部npmライブラリを利用できる構成も検討してください。

変換JavaScriptの変更が次回実行時に確実に反映されるようにしてください。

### 3.3 手動実行コマンド

次の2つのコマンドを用意してください。

**A. 変換処理を選択して実行**

1. VS Codeで入力ファイルを開く。
2. コマンドを実行する。
3. JavaScriptの候補一覧を表示する。
4. ユーザーが変換処理を選択する。
5. JavaScriptを実行する。
6. Markdownプレビューを表示・更新する。

**B. 前回の変換を再実行**

1. 前回の入力ファイルと変換JavaScriptを再利用する。
2. 選択操作なしで再実行する。
3. プレビューを更新する。

いずれもVS Codeのコマンドパレットから利用できるようにしてください。キーボードショートカットも割り当て可能にしてください。

### 3.4 Markdownプレビュー

原則として、VS Code標準のMarkdownプレビューを使用してください。

独自のWebviewによるMarkdownレンダラーを最初から実装することは避けてください。

表示の更新条件は以下です。

- 入力ファイルを変更・保存しても更新しない。
- 変換JavaScriptを変更・保存しても更新しない。
- 自動保存設定は変更しない。
- 手動で変換を実行したときだけ更新する。
- 実行エラーの場合は、前回成功したプレビューを保持する。

可能なら、生成したMarkdownでワークスペースを汚さない方式を優先してください。

ただし、標準Markdownプレビューとの互換性、安定性、保守性を優先して実装方式を判断してください。

### 3.5 エラー処理

以下を適切に処理してください。

- 入力ファイルが存在しない。
- 変換JavaScriptが存在しない。
- JavaScriptの構文エラー。
- JavaScript実行中の例外。
- Markdown文字列以外が返された。
- JavaScript実行が終了しない。

失敗した場合、既存のプレビューを破壊せず、原因を確認できるエラーメッセージを表示してください。

### 3.6 安全性

ワークスペースの信頼状態を考慮し、未信頼のJavaScriptを無条件に実行しないでください。

ユーザーの元ファイルは原則として読み取り専用で扱ってください。

既存ファイルの変更が必要な場合、元ファイルを上書きせず、同じディレクトリ内で所定のバックアップ名へ改名してから更新版を作成してください。

## 4. 開発方針

以下を優先してください。

1. 変換処理の自由度
2. 手動実行の確実性
3. VS Code標準機能との互換性
4. 操作の簡潔さ
5. 保守性
6. 将来的な機能拡張

変換処理の具体的な内容は実装しないでください。

ただし、動作確認用として入力文字列をそのまま返すサンプルJavaScriptは用意してください。

過剰に複雑な設計は避けてください。
