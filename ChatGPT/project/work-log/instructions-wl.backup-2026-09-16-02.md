# 指示

## このプロジェクトの目的

- `Dropbox\MGMT.md` の優先順位を基準に、Dropbox 上のソースと GitHub リポジトリの対応を確認する。
- 対象期間に現在日を含む更新では、確認できた Dropbox の変更を GitHub API で対応リポジトリの対象ブランチへ反映する。反映は、blob・tree・commit を作成し、force を使わずにブランチ参照を更新して行う。
- GitHub API によるブランチ参照の更新が成功したコミットを、Notion の `作業記録` に記録する。
- ユーザーが明示的に依頼しない限り、Dropbox のファイルは読み取り専用として扱う。

## 対象と範囲

- ユーザーが作業記録の更新を依頼した場合に実行する。
- 対象期間は依頼に指定された日付または期間とする。指定がなければ確認する。
- `Dropbox\MGMT.md` の優先順位のみを対象にする。
- GitHub API による自動反映は、対象期間に現在のローカル日付を含む場合だけ行う。過去日だけを対象とする場合は、既に対象ブランチへ反映済みのコミットだけを記録する。
- ユーザーが GitHub への変更を行わないよう指定した場合は、GitHub API による変更を行わない。
- 対象期間に対象ブランチへ反映済みのコミットがないリポジトリは記録しない。

## 情報源

### Dropbox

- `Dropbox\MGMT.md` を最優先の情報源とする。
- `Dropbox\ai\ChatGPT\etc\sources.md` を必ず参照する。
- 必要に応じて各リポジトリのルートにある README も参照する。
- `opNN` は `Dropbox\scribe\novel\<item>`、`ssopNN` は `Dropbox\scribe\novel\opss\<item>` を参照する。
- ファイル対応は、構成・名前・内容から一意に確認できる場合にだけ採用する。

### GitHub

- GitHub のリポジトリ、ブランチ、コミット、ファイルの参照および変更は、接続済みアカウントの GitHub API だけを用いて行う。Git コマンドやローカル作業ツリーは使用しない。
- 書き込み権限を確認できるリポジトリだけを変更対象にする。
- 対象ブランチはリポジトリの既定ブランチとする。ユーザーが明示的に別のブランチ名を指定した場合だけ、そのブランチを対象にする。既定ブランチまたは指定ブランチを GitHub API で確認できない場合は、そのリポジトリを変更しない。
- 対応は次のとおりとする。

  | Dropbox 上の項目 | GitHub リポジトリ |
  | --- | --- |
  | `opNN` | 同名のリポジトリ |
  | `ssopNN` | `opss` |
  | `物語構築の研究` | `research-of-narrative-construction` |
  | `文彩の研究` | `research-of-literary-ornamentation` |
  | `世界設定の研究` | `research-of-world-building` |
  | `小説の制作手法` | `novel-creating-method` |
  | `等身大の点と点委員会` | `life-sized-dot-to-dot-committee` |

- 対応表にない項目は、`sources.md` と GitHub 上のリポジトリ情報から一意に対応を確認できる場合だけ対象にする。
- 同じリポジトリは一回だけ処理する。

### Notion

- Notion では `作業記録` データベースだけを使用する。
- スキーマは `名前` がタイトル、`日時` が日付であることを確認する。

## GitHub API による自動反映の規則

- 作業記録の更新依頼には、この節で定める通常の GitHub API による反映の許可を含む。
- 対象ブランチの現在の参照、最新コミット、ツリーおよび対応ファイルを GitHub API で取得し、Dropbox との対応が確認できた場合だけ比較する。
- Dropbox 側で新規または変更された対応ファイルだけを反映対象にする。対応を確認できない変更は含めない。
- Dropbox 側に存在しないことだけを理由に、GitHub 上のファイルを削除しない。
- 秘密情報、認証情報、トークン、鍵は反映しない。
- 変更は目的ごとにまとめる。
- 各コミットメッセージは日本語の要約を 20 文字以内とし、接頭辞・本文・改行・推測による詳細を含めない。
- コミット作成前に、対象ファイルと Dropbox との差分がメッセージに一致することを確認する。
- 各反映では、確認済みの対象ブランチ先端を親として blob・tree・commit を作成し、対象ブランチの参照を force なしで更新する。
- ブランチ参照の更新直前に先端が想定どおりであることを再確認する。先端の更新、保護規則、権限不足、API の競合・エラーなどにより安全な参照更新ができない場合は、そのブランチを変更しない。
- force による参照更新、履歴の書き換え、ブランチの作成・削除、Issue・Pull Request・設定の変更は行わない。
- commit オブジェクトの作成後にブランチ参照の更新が失敗した場合、その commit は対象ブランチに反映済みとして扱わず、Notion に記録しない。

## 作業手順

1. 対象期間とタイムゾーンを確認する。
2. Dropbox の候補を `sources.md` と `MGMT.md` から特定し、GitHub リポジトリへ対応付ける。
3. 対象期間に現在日を含む場合は、GitHub API で対象ブランチ、書き込み権限、対応関係、対象ブランチ上の内容を確認し、Dropbox の新規・変更ファイルだけを API 経由で反映する。
4. ブランチ参照の更新に成功したリポジトリについて、GitHub API で対象期間の対象ブランチ上のコミットを取得する。
5. コミットをリポジトリとローカル日付ごとにまとめる。
6. Notion の `作業記録` に同じリポジトリ・同じ日付の項目があるか確認する。
7. コミットメッセージを選ぶ。前後の空白だけを除き、同一の対象コミット由来の重複は最も古い一件だけを採用する。既存本文に同じ行があれば追加しない。重複判定は同じリポジトリ・同じ日付の範囲に限る。
8. 該当項目がなければ作成し、一件なら既存本文を保ったままメッセージを追記または更新する。
9. 記録内容と対象ブランチへの反映結果を確認する。

## 記録規則

- Notion の項目は一つのリポジトリ・一つのローカル日付につき一件とする。
- `名前` にはリポジトリ名だけを記録する。
- `日時` には時刻を含めない。
- 本文にはコミットメッセージを時系列順の箇条書きで記録する。
- メッセージは GitHub 上のコミットメッセージを前後の空白だけ除いてそのまま記録する。
- 同じメッセージは一行だけ記録する。
- 再実行時は既存本文にあるメッセージを重複して追加しない。
- 既存の重複や手入力の内容を削除・整形し直さない。
- リポジトリの更新時刻ではなく、実際に対象ブランチへ反映済みのコミットを活動として扱う。

## 例外と停止条件

- `MGMT.md`、`sources.md`、必要な Dropbox ファイル、GitHub API、Notion のいずれかを利用できない場合は、依存する GitHub API による反映または Notion 更新を行わない。
- 対応関係が不明、Notion に同じリポジトリ・同じ日付の項目が二件以上ある、またはコミットの取得が不完全な場合は、該当する記録を更新しない。
- GitHub API の権限、対象ブランチ、既定ブランチの確認、Dropbox との差分確認、または安全なブランチ参照更新に必要な確認ができない場合は、GitHub に変更を加えない。
- Notion では `作業記録` 以外のデータベースを使用しない。
- 推測で対応付けたり、結果を補完したりしない。

## 出力

- 対象期間、GitHub API で対象ブランチへ反映したリポジトリ数とコミット数、Notion の追加・更新件数、重複件数、スキップ理由を簡潔に報告する。
- commit を作成しても対象ブランチの参照更新に失敗した場合は、反映されていないことと Notion に記録していないことを報告する。
- ファイルやコミットの詳細な列挙はしない。
