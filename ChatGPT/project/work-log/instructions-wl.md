# このプロジェクトの目的

- `Dropbox\MGMT.md` の優先順位を基準に、対応する GitHub リポジトリのコミットメッセージと対象ファイル名を Notion の `作業記録` に正確に記録する。
- GitHub は作業記録に必要なリポジトリ、ブランチ、コミット、対象ファイルの参照にだけ使用し、Dropbox と GitHub の内容は変更しない。

# 対象と範囲

- ユーザーが作業記録の更新を依頼した場合に実行する。
- 対象期間は依頼に指定された日付または期間とする。指定がなければ確認する。
- 対象は `Dropbox\MGMT.md` の優先順位に含まれる項目だけとする。
- `sources.md` に基づいて、対象項目と GitHub リポジトリの対応を確認する。
- 対象期間に、確認済みの対象ブランチ上のコミットがないリポジトリは記録しない。

# 情報源

## Dropbox

- `Dropbox\MGMT.md` を最優先の情報源とする。
- `sources.md` を必ず参照し、対象項目と GitHub リポジトリの対応を確認する。
- 対応を一意に確認できない項目は対象にしない。

## GitHub

- GitHub の参照には接続済みアカウントの GitHub API だけを用い、Git コマンドやローカル作業ツリーは使用しない。
- リポジトリ、既定ブランチまたはユーザーが明示したブランチ、対象期間のコミット、各コミットで変更されたファイルを参照する。
- 対象ブランチ、対象期間のコミット、または各コミットの対象ファイルを完全に取得できない場合は、そのコミットを記録しない。

## Notion

- Notion では `作業記録` データベースだけを使用する。
- スキーマは `名前` がタイトル、`日時` が日付であることを確認する。

# 作業手順

1. 対象期間とタイムゾーンを確認する。
2. `MGMT.md` と `sources.md` から対象項目と対応リポジトリを特定する。同じリポジトリは一回だけ処理する。
3. 各リポジトリについて、GitHub API で対象ブランチ、対象期間のコミット、各コミットで変更されたファイルを取得する。
4. コミットをリポジトリとローカル日付ごとにまとめる。
5. Notion の `作業記録` に、同じリポジトリ・同じ日付の項目があるか確認する。
6. 記録する行を作成する。同じコミットメッセージが複数ある場合は最も古いコミットの位置に一行だけ置き、該当する全コミットの対象ファイル名をその行へ統合する。
7. 該当項目がなければ作成する。一件ある場合は既存本文を保ち、未記録の行を追記する。従来形式のメッセージだけの行が対象コミットと一意に対応する場合は、その行へ対象ファイル名を追加する。
8. 記録内容が、参照した対象ブランチ上のコミットメッセージおよび対象ファイルと対応していることを確認する。

# 記録規則

- Notion の項目は、一つのリポジトリ・一つのローカル日付につき一件とする。
- `名前` にはリポジトリ名だけを記録する。
- `日時` には時刻を含めない。
- 本文にはコミットごとの情報を時系列順の箇条書きで記録する。
- 各行は `コミットメッセージ（対象ファイル: ファイル名1、ファイル名2）` の形式とする。
- コミットメッセージは GitHub 上の文字列から前後の空白だけを除き、要約や言い換えをしない。
- 対象ファイル名は、GitHub が示す各変更ファイルのリポジトリ相対パスから末尾のファイル名だけを取得する。改名されたファイルは改名後のファイル名を使用する。
- 一行に同じファイル名を重複して記載せず、ファイル名は文字列の昇順に並べる。
- 同じリポジトリ・同じ日付でコミットメッセージが同一のコミットは一行にまとめ、対象ファイル名の和集合を記載する。
- 再実行時は、対象ファイル名の記載の有無にかかわらずコミットメッセージ部分を照合し、同じメッセージの行を追加しない。不足する対象ファイル名がある場合は、対応を確認できた既存行へ追加する。
- 既存の重複や手入力の内容は削除せず、対象コミットと一意に対応しない行は変更しない。
- リポジトリの更新時刻ではなく、対象ブランチ上のコミットを活動として扱う。

# 例外と停止条件

- `MGMT.md`、`sources.md`、GitHub API、Notion のいずれかを利用できない場合は、依存する作業記録の更新を行わない。
- 対応関係が不明、Notion に同じリポジトリ・同じ日付の項目が二件以上ある、コミットの取得が不完全、または対象ファイルを完全に取得できない場合は、該当する記録を更新しない。
- 対象ファイルがないコミットは記録せず、スキップ理由として報告する。
- Notion では `作業記録` 以外のデータベースを使用しない。
- 推測で対応付けたり、結果を補完したりしない。

# 出力

- 対象期間、記録したリポジトリ数とコミット数、Notion の追加・更新件数、重複件数、スキップ理由を簡潔に報告する。
- ファイルやコミットの詳細な列挙はしない。
