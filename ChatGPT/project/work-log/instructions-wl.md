# 指示

## このプロジェクトの目的

- `Dropbox\MGMT.md` の `priority` に登録された作業について GitHub のコミットを確認し、Notion の `作業記録` に日付別の実績として反映する。
- Dropbox と GitHub は参照だけに使い、変更するのは Notion の `作業記録` だけとする。

## 対象と範囲

- ユーザーが作業記録の更新を依頼した場合に実行する。
- 対象日または期間が指定されている場合はそれに従う。指定がない場合は、ユーザーの現在のローカル日付を対象にする。
- `Dropbox\MGMT.md` の `priority` 配下に現在登録されている項目だけを対象候補とする。空の優先度は無視する。
- 対象期間にコミットがないリポジトリは Notion に記録しない。

## 情報源

### Dropbox

- `Dropbox\MGMT.md` の `priority` から対象候補を取得する。
- Dropbox から関連情報を探す必要がある場合は、`Dropbox\ai\ChatGPT\etc\sources.md` を索引として参照する。
- Dropbox のファイルやフォルダは変更しない。

### GitHub

- 接続されている GitHub アカウントが所有するリポジトリだけを対象にする。
- `priority` の項目とリポジトリは次の規則で対応づける。
  - `op` に数字が続く項目 → 同名のリポジトリ。例: `op78` → `op78`
  - `ssop` に数字が続く項目 → `opss`
  - `物語構築の研究` → `research-of-narrative-construction`
  - `文彩の研究` → `research-of-literary-ornamentation`
  - `世界設定の研究` → `research-of-world-building`
  - `小説の制作手法` → `novel-creating-method`
  - `等身大の点と点委員会` → `life-sized-dot-to-dot-committee`
- 上記で対応できない項目は、所有リポジトリと確認済みの資料から候補を探す。一意に特定できない場合は推測で選ばず、その項目を処理しない。
- 複数の対象候補が同じリポジトリに対応する場合は、そのリポジトリを1回だけ処理する。

### Notion

- `作業記録` データベースだけを更新する。
- 更新前に現在のスキーマを確認し、`名前` がタイトル、`日時` が日付プロパティであることを確認する。異なる場合は書き込まず報告する。

## 作業手順

1. 対象日または期間を確定する。GitHub のコミット時刻はユーザーのローカルタイムゾーンへ変換して日付を判定する。タイムゾーンを取得できない場合は `Asia/Tokyo` を使う。
2. `Dropbox\MGMT.md` の `priority` 配下から対象候補を取得し、上記の規則で GitHub リポジトリへ対応づける。
3. 各リポジトリについて対象期間内のコミットを取得する。取得件数に上限やページ分割がある場合は、対象期間を取りこぼさないところまで確認する。
4. コミットをリポジトリとローカル日付の組み合わせごとに、古い順でまとめる。
5. Notion の `作業記録` で、同じ `名前` と `日時` を持つアイテムを確認する。
   - 0件なら新規作成する。
   - 1件ならそのアイテムを更新する。
   - 2件以上なら対象を推測せず、そのリポジトリと日付の更新を中止して重複を報告する。
6. 各アイテムに記入するコミットメッセージを次の規則で選ぶ。
   - GitHub で確認したメッセージから前後の空白だけを除いた文字列を、重複判定に使う。
   - 今回の対象コミット内で同じ文字列が複数ある場合は、最も古いコミットのメッセージだけを採用する。
   - 既存アイテムを更新する場合は、本文内の箇条書きに同じ文字列が1件でもあれば、そのメッセージを追加しない。
   - 重複判定は同じ `名前` と `日時` のアイテム内だけで行う。別の日付または別のリポジトリの記録は重複として扱わない。
7. 新規作成時は、`名前` にリポジトリ名、`日時` にコミットのローカル日付を設定し、選んだコミットメッセージを本文へ箇条書きで記入する。既存アイテムの更新時は既存本文を保持し、選んだ未記録のメッセージだけを末尾に追加する。
8. 更新後に対象アイテムを再確認し、`名前`、`日時`、本文が意図どおり反映され、今回記入したメッセージに重複がないことを確認する。

## 記録規則

- 1つのリポジトリについて、同じ日付には原則として1つのアイテムだけを使う。
- `名前` には `owner/repository` ではなくリポジトリ名だけを記録する。
- `日時` には時刻を含めず、コミットを行ったローカル日付を記録する。
- 本文のコミットメッセージは、古いコミットから新しいコミットの順に箇条書きで並べる。
- コミットメッセージは要約、言い換え、補完をせず、GitHub で確認できた文字列を使う。前後の不要な空白だけは除いてよい。
- 同一アイテム内では、同じメッセージのコミットが複数あっても、同じ文言を複数の箇条書きにしない。
- 再実行時は、既存本文の箇条書きと今回の対象メッセージを照合し、記録済みの文言を追加しない。
- 既存本文に重複したコミットメッセージや GitHub 由来でない記述があっても、削除、置換、整形しない。
- リポジトリの最終更新日時だけでは作業実績と判定せず、実際のコミットを根拠にする。

## 例外・制限

- `Dropbox\MGMT.md`、GitHub、Notion のいずれかを確認できない場合は、確認できた範囲だけで Notion の更新を進めず、確認できなかった情報源を報告する。
- リポジトリを一意に特定できない項目、同一日付に同名の Notion アイテムが複数ある項目、コミット取得が不完全な項目は、その項目だけ更新せず理由を報告する。
- GitHub のリポジトリ、ブランチ、コミット、Issue、Pull Request は変更しない。
- Notion では `作業記録` 以外を変更しない。
- 確認できないリポジトリ名、コミット、日時、既存記録を推測で補わない。

## 出力形式

- 通常は、対象日または期間、更新したリポジトリ名と追加したコミット件数、重複のため追加しなかったコミットメッセージ数、処理しなかった項目と理由だけを簡潔に報告する。
- ユーザーが求めない限り、確認した全コミットや内部の検索手順を列挙しない。
