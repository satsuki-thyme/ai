# 指示

## このプロジェクトの目的

- `Dropbox\MGMT.md` の優先順位を基準に、対応する GitHub リポジトリのコミットを Notion の `作業記録` に正確に記録する。
- GitHub は作業記録に必要なリポジトリ、ブランチ、コミットの参照にだけ使用し、Dropbox と GitHub の内容は変更しない。

## 対象と範囲

- ユーザーが作業記録の更新を依頼した場合に実行する。
- 対象期間は依頼に指定された日付または期間とする。指定がなければ確認する。
- 対象は `Dropbox\MGMT.md` の優先順位に含まれる項目だけとする。
- `Dropbox\ai\ChatGPT\etc\sources.md` に基づいて、対象項目と GitHub リポジトリの対応を確認する。
- 対象期間に、確認済みの対象ブランチ上のコミットがないリポジトリは記録しない。

## 情報源

### Dropbox

- `Dropbox\MGMT.md` を最優先の情報源とする。
- `Dropbox\ai\ChatGPT\etc\sources.md` を必ず参照し、対象項目と GitHub リポジトリの対応を確認する。
- 対応を一意に確認できない項目は対象にしない。

### GitHub

- GitHub の参照には接続済みアカウントの GitHub API だけを用い、Git コマンドやローカル作業ツリーは使用しない。
- リポジトリ、既定ブランチまたはユーザーが明示したブランチ、対象期間のコミットを参照する。
- 対象ブランチを確認できない場合、または対象期間のコミットを完全に取得できない場合は、そのリポジトリを記録しない。

### Notion

- Notion では `作業記録` データベースだけを使用する。
- スキーマは `名前` がタイトル、`日時` が日付であることを確認する。

## 作業手順

1. 対象期間とタイムゾーンを確認する。
2. `MGMT.md` と `sources.md` から対象項目と対応リポジトリを特定する。同じリポジトリは一回だけ処理する。
3. 各リポジトリについて、GitHub API で対象ブランチと対象期間のコミットを取得する。
4. コミットをリポジトリとローカル日付ごとにまとめる。
5. Notion の `作業記録` に、同じリポジトリ・同じ日付の項目があるか確認する。
6. コミットメッセージを選ぶ。前後の空白だけを除き、同一コミット由来の重複は最も古い一件だけを採用する。既存本文に同じ行があれば追加しない。重複判定は同じリポジトリ・同じ日付の範囲に限る。
7. 該当項目がなければ作成し、一件なら既存本文を保ったままメッセージを追記または更新する。
8. 記録内容と、参照した対象ブランチ上のコミットが対応していることを確認する。

## 記録規則

- Notion の項目は、一つのリポジトリ・一つのローカル日付につき一件とする。
- `名前` にはリポジトリ名だけを記録する。
- `日時` には時刻を含めない。
- 本文にはコミットメッセージを時系列順の箇条書きで記録する。
- メッセージは GitHub 上のコミットメッセージを、前後の空白だけ除いてそのまま記録する。
- 同じメッセージは一行だけ記録する。
- 再実行時は既存本文にあるメッセージを重複して追加しない。
- 既存の重複や手入力の内容を削除・整形し直さない。
- リポジトリの更新時刻ではなく、対象ブランチ上のコミットを活動として扱う。

## 例外と停止条件

- `MGMT.md`、`sources.md`、GitHub API、Notion のいずれかを利用できない場合は、依存する作業記録の更新を行わない。
- 対応関係が不明、Notion に同じリポジトリ・同じ日付の項目が二件以上ある、またはコミットの取得が不完全な場合は、該当する記録を更新しない。
- Notion では `作業記録` 以外のデータベースを使用しない。
- 推測で対応付けたり、結果を補完したりしない。

## 出力

- 対象期間、記録したリポジトリ数とコミット数、Notion の追加・更新件数、重複件数、スキップ理由を簡潔に報告する。
- ファイルやコミットの詳細な列挙はしない。
