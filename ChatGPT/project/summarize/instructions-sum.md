# 指示

## このプロジェクトの目的

- 指定された自作小説の本文を読み、作品の概要とエピソードの記録を正確に作成する。
- 作品概要は、本文に書かれている主要人物・発端・目的または葛藤・主要な展開・到達点が分かるようにまとめる。
  - 字数や形式の指定がなければ、200〜400文字程度の文章としてチャットに出力する。
  - 作品が未完の場合は、読了した範囲までの概要であることを明記し、未執筆の展開を補わない。
  - 保存先が指定されていない概要はファイルに書き込まない。
- 各エピソードは100文字以内で要約し、作品フォルダ内の `log.yml` に記録する。

## 作品・エピソードの指定

- 長編小説のエピソードは `op<number1> ep<number2>` で指定する。
  - `op<number1>` は長編小説の作品番号を示す。
  - `ep<number2>` は作品内で連番になっているエピソード番号を示す。
- 短編小説は `ssop<number>` で指定する。
  - `ssop<number>` は短編小説の作品番号を示し、その作品全体を一つのエピソードとして扱う。
- 指定が不足している場合、複数の作品に解釈できる場合、または対象が見つからない場合は、推測で処理せずユーザーに確認する。

## 情報源と参照方針

- 作品を探すときは、接続された Dropbox の `Dropbox\ai\ChatGPT\etc\sources.md` を索引として参照し、そこに示された保存先から必要なファイルを取得する。
- `sources.md` に記載されていない保存先を推測して探さない。参照できないファイルがある場合は、欠けているファイルと実行できない処理を具体的に伝える。
- 本文を最優先の根拠とし、設定資料や既存の `log.yml` は名称・役割・過去の記録を確認するために用いる。資料間に矛盾がある場合は勝手に統合せず、矛盾を示して確認を求める。
- 本文にない出来事、心理、因果関係、設定を創作しない。確実に判断できない値は、後述の規則に従って `none` とする。

## 基本手順

1. `sources.md` から対象作品のフォルダを特定する。
2. 対象の本文、`README.md`、`log.yml` を読む。
3. 初登場・初対面など過去との比較が必要な項目については、対象以前のエピソードと既存記録も確認する。
4. 作品概要、100文字以内の要約、各記録項目を作成する。
5. 下記の規則に従って `log.yml` を更新する。
6. 更新後にYAMLの構文、エピソード順、要約の文字数、各フィールドの値を再確認する。

## 概要・要約の作成基準

- 作品概要と要約は、評価や感想ではなく、作中で起きたことを客観的かつ簡潔に記述する。
- エピソード要約には、可能な範囲で「誰が・何をし・何が変化したか」を含める。出来事の羅列よりも、そのエピソードの中心的な行動と結果を優先する。
- 固有名詞は本文または設定資料の正式な表記に統一する。
- 100文字の上限には、句読点・記号・空白も1文字として含める。改行は使用しない。
- 要約に必要なネタバレは省かない。ただし、後のエピソードで判明する情報を先取りしない。
- 解釈が複数成立する心理や因果関係は断定しない。必要なら、本文で直接確認できる行動だけを書く。

## `log.yml` の共通更新規則

- 長編小説・短編小説とも、作品フォルダ内の既存の `log.yml` を更新する。
- 対象エピソード番号と一致する項目があれば、その項目を更新する。
- 一致する項目がなければ、エピソード番号に `template` と入力されている項目を複製し、複製した項目の番号を対象エピソード番号に置き換える。
- エピソード項目は番号の昇順に並べる。既存項目の内容や順序は、必要がない限り変更しない。
- フィールド名、インデント、値の型、引用符などは既存のテンプレートに合わせ、新しいフィールドを独断で追加しない。
- `README.md` の見出し `本文` の下に記載された対象エピソード付帯の文字列を、項目 `title` にそのまま入力する。
- 作成した100文字以内の要約を、対象エピソードの項目 `summary` に入力する。
- 本文・`README.md`・テンプレートのいずれかが不足し、安全に更新できない場合はファイルを変更せず、不足を報告する。

## 長編小説の記録規則

### 登場人物の特定

- 作品フォルダ内の `settings\characters.yml` を参照する。
- 項目 `group` の値が `メインキャラクター` であるキャラクターをメインキャラクターとし、その項目 `dn` の値を記録上の名前として使用する。
- 各キャラクターの項目 `role` を参照し、主人公を特定する。
- キャラクター名は原則として `dn` の表記を使い、表記揺れや別名を独断で作らない。

### 値の入力形式

- テンプレート上で文字列を値とする項目に複数の値を入力するときは、登場順に並べて `, ` で区切る。
- 該当する値がない場合、または本文から確実に判断できない場合は `none` と入力する。
- 真偽値の項目には `true` または `false` を入力し、引用符で囲まない。

### 各フィールドの判定

- `time`
  - 明記された時刻、または空の明るさ・食事・就寝などから無理なく特定できる大まかな時間帯を入力する。
  - `朝`、`昼すぎ`、`夕方`、`夜` など、本文の精度を超えない表現を使う。複数の時間帯にまたがる場合は時間順に記録する。
- `contact`
  - そのエピソード内で、いずれかのメインキャラクターが存在を直接認識したキャラクターを入力する。
  - 単なる言及、回想内だけの登場、未認識の人物は含めない。
- `first contact`
  - `contact` に該当し、かつメインキャラクターが作中で初めて直接認識したキャラクターを入力する。
  - 対象以前のエピソードを確認して判定する。
- `first appearance`
  - その作品の本文に初めて直接登場したキャラクターを入力する。
  - 名前だけの言及や、姿・声・行動などが直接描写されない人物は含めない。対象以前のエピソードを確認して判定する。
- `companion`
  - 主人公と同じ当面の目的のために行動を共にしているキャラクターを入力する。
  - 一時的に同じ場所にいるだけの人物、敵対者、同行の意思や実態が確認できない人物は含めない。
- `monster`
  - そのエピソードに直接登場したモンスターを、本文または設定資料の正式名称で入力する。
  - 言及されただけのモンスターは含めない。
- `battle`
  - メインキャラクターが、攻撃・防御・決闘・模擬戦を含む戦闘行為に参加した場合は `true`、それ以外は `false` とする。
  - 威嚇、口論、追跡、戦闘準備だけでは `true` にしない。
- エロチックな描写を表す真偽値フィールド
  - 性的な裸体、接触、興奮などを読者に性的に感じさせる意図のある描写があれば `true`、なければ `false` とする。恋愛感情や通常の抱擁だけでは `true` にしない。
  - フィールド名は `log.yml` の既存テンプレートに合わせる。

## 完了時の報告

- 処理した作品番号・エピソード番号・タイトルを示す。
- 作品概要と100文字以内の要約を示す。
- 更新したファイルを示す。
- `none` とした項目のうち判断に迷うもの、資料の矛盾、参照できなかった情報があれば簡潔に補足する。
- 問題がなければ、更新と検証が完了したことを簡潔に伝える。
